## The problem

People ask Copilot things like "why is my laptop so slow" or "my wifi keeps dropping." Copilot used to answer from the outside, with the generic checklist (restart, update your drivers, run the troubleshooter) that people had usually tried already. The answer to most PC problems lives in local state a chat model can't see: event logs, driver versions, battery reports, disk usage and adapter settings. So the gap wasn't only model intelligence. Copilot had no way to look at the machine it was supposed to fix.

## What I owned

I owned product definition for **diagnostics in Copilot Tasks**, the capability that lets Copilot generate code and run it locally on a person's Windows PC. Copilot writes a diagnostic, runs it on the device, reads the output and reasons from what it actually found.

## The calls I made

Running model-written code on someone's personal computer is a big ask, so most of the product work was deciding exactly when and how Copilot gets to do it.

- **Ask before running anything.** I designed the consent flows. Copilot asks before it runs code and says in plain language what the script will read and what it will change, so the person at the keyboard decides with the facts in front of them.
- **Set a readiness bar before real users.** A model that writes a wrong diagnostic wastes someone's afternoon, and one that writes an unsafe one does worse. I defined the criteria a model had to meet before it could generate and execute code for real users, and the evals behind them.
- **Draw the line between acting alone and asking first.** I set the execution guardrails and the human-approval boundaries: what the agent can do on its own and what always needs a person to approve. That included the MCP permission patterns for exposing OS capabilities to the agent as tools.
- **Give Copilot the machine's context.** I shipped Copilot and Windows integrations that surface richer system context, so answers start from the PC's real state instead of a guess.

## Outcome

Diagnostics shipped to **10M+ Windows Copilot users**. Troubleshooting moved from "here are 6 things to try" toward "here is what I found on this PC, and here is a fix if you want it", inside boundaries that decide what Copilot may do alone and what it has to ask about first.

## What I learned

Agents on a personal computer are a trust product before they are a model product. The hardest calls on this project were rarely about what the model could do. They were about what it should be allowed to do without asking, and how to make that boundary obvious to the person at the keyboard.
