## The problem

AI assistants are built for one person at a time. Each session starts from a blank prompt, what one person works out stays in their own history, and a fix that helps one teammate never reaches the next. A team that works this way gets faster one person at a time, but never together.

## How it works

The system runs on three ideas:

- **It's multiplayer.** Teammates see each other's sessions and build on each other's work instead of starting over.
- **Its users can change it.** Anyone using it can make changes to its code base, so whoever hits a gap can close it.
- **It improves itself.** The system learns recursively, so it gets better the more the team works in it.

## From one team to the org

It started as one team's project. It now runs across 5+ teams and 300+ people in the org, and every one of those people can change it.

## What I own

I design its product features and set the vision for where it goes: what a team should be able to see, share and change, and what working together looks like when everyone on the team works with AI.

## What I'm working out

Single-player AI made each of us faster. The question I'm working on is what makes a team faster: which work should be shared by default, how a team trusts a change someone else made to a system everyone depends on, and how a system that learns from everyone keeps working for each person. Answering that is how I'm defining a new way to work as a team in the AI era.
